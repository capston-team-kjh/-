# FocusAI 학습 장면 준비 설계

## 목표

컴퓨터의 영상 파일을 전수 목록화하고, 그중 FocusAI 촬영 원본을 모두 분석하여 학습에 유효한 장면만 상태별 MP4 클립으로 분할한다. 원본 영상은 수정하지 않는다. 결과는 사람이 빠르게 검토할 수 있어야 하며, 작업 종료 시 현재 영상만으로 충분하지 않은 장면을 정량·정성 기준으로 보고한다.

이번 작업은 학습 데이터 준비까지를 범위로 한다. 모델 재학습, 모델 교체, 운영 분석 규칙 변경은 포함하지 않는다.

## 확인된 입력 범위

- 로컬 고정 드라이브: `C:` 1개
- 영상 확장자 후보: 1,414개
- `.mts` 후보 1,242개 중 1,239개는 프로젝트 `node_modules`의 TypeScript 선언 파일이고 3개도 프로그램 자산의 코드 파일이므로 영상에서 제외한다.
- FocusAI 관련 영상 경로: 27개
- `C:\Projects\session_54_full.webm`은 프로젝트 내부 `54_8_chunk_1_af2741b62ac0.webm`과 SHA-256이 같은 중복 파일이다.
- 실제 처리할 고유 FocusAI 원본: 26개, 총 약 8.08시간
- Windows, Program Files, Riot Games 아래의 게임·프로그램 동영상 자산은 `source_inventory.csv`에 제외 사유를 기록하고 장면 분석에서는 제외한다.

## 방식 선택

기존 FocusAI 분석기는 현재 `drowsy`, `gaze_down`, 필기·독서 중의 `focus`를 자주 혼동한다. 따라서 기존 판정을 그대로 학습 라벨로 사용하지 않는다.

1. 모든 고유 FocusAI 원본을 1 FPS로 분석하여 상태 변화와 특징 플래그 후보를 찾는다.
2. 전체 구간을 10초 간격으로 균일 표본화하여 기존 분석기가 놓친 장면과 오탐 후보를 찾는다.
3. 상태 변화 전후와 희소 상태 후보는 더 촘촘하게 프레임을 확인한다.
4. 명확한 장면만 상태별 폴더에 넣고, 경계가 모호하거나 두 상태가 겹치는 장면은 `needs_review`로 보낸다.

이 방식은 모든 원본을 분석하면서도 기존 모델의 의사 라벨 오류를 그대로 복제하지 않는다.

## 필요한 장면과 판정 기준

### 학습 대상 상태

- `focus`: 화면 보기, 타이핑, 독서, 필기처럼 학습 행동이 이어지는 상태. 고개가 아래로 향해도 손·교재 활동이 이어지면 `focus`로 본다.
- `drowsy`: 눈 감김, 고개 떨굼, 움직임 감소와 학습 행동 중단이 지속되는 상태. 짧은 눈 감김이나 단순 고개 숙임은 포함하지 않는다.
- `gaze_down`: 학습 행동과 관계없이 아래를 지속해서 보거나 책상 아래·휴대폰 등을 보는 상태.
- `gaze_side`: 머리나 눈이 좌우의 학습 외 대상을 지속해서 보는 상태.
- `unknown`: 얼굴 가림, 극심한 역광·저조도, 프레임 손상 또는 얼굴 검출 불안정으로 다른 상태를 신뢰성 있게 판단할 수 없는 장면.

### 규칙 검증용 상태

- `absent`: 전면·상단 카메라 문맥에서 사람이 자리를 비운 것이 명확한 상태.
- `bad_posture`: 몸 기울임, 과도한 웅크림, 비정상 자세가 지속되지만 졸음으로 확정할 근거는 부족한 상태.

`absent`와 `bad_posture`는 현재 `train_state_classifier.py`에서 학습 대상에서 제외되므로 `rule_validation` 아래에 분리한다.

### 우선 수집할 어려운 경계

1. 필기·독서 중 고개를 숙인 `focus` 대 학습 외 `gaze_down`
2. 활동 중 고개 숙임 대 눈 감김·고개 떨굼이 지속되는 `drowsy`
3. 짧은 주변 확인 대 지속적인 `gaze_side`
4. 실제 자리 비움 대 얼굴만 검출되지 않는 `unknown`
5. 자세 불량 대 졸음

## 분할 규칙

- 출력은 현재 병합 카메라 분석과 호환되도록 원본의 전체 화면 구성을 유지한다.
- 같은 상태의 인접 후보는 사이 간격이 2초 이하이면 하나로 합친다.
- 각 장면 앞뒤에 최대 2초의 문맥을 포함하되 원본 범위를 넘지 않는다.
- `drowsy`는 지속성을 확인할 수 있도록 원칙적으로 12초 이상으로 만든다.
- 그 밖의 상태는 행동이 판별되는 4초 이상 구간만 사용한다.
- 검토 편의를 위해 한 클립은 최대 30초로 제한하고, 긴 구간은 의미가 끊기지 않는 지점에서 나눈다.
- 서로 다른 상태가 명확히 겹치거나 경계가 불확실하면 임의로 확정하지 않고 `needs_review`로 보낸다.
- 동일 원본 중복과 동일 시간 범위 중복을 제거한다.
- 영상은 MP4로 저장하며 음성은 학습 판정에 사용하지 않는다.

## 파일명과 추적 정보

파일명은 ASCII로 유지해 학습 도구 호환성을 보호한다.

```text
<label>__<scene-cue>__<source-id>__<start>-<end>.mp4
```

예:

```text
drowsy__eyes-closed_head-drop__S002_test__004965-004983.mp4
focus__writing_head-down__session54__000120-000134.mp4
gaze_side__looking-phone-right__session71__001840-001850.mp4
```

`clips_manifest.csv`에는 최소한 다음 정보를 기록한다.

- 클립 경로와 라벨
- 사람이 이해할 수 있는 장면 설명
- 원본 절대 경로와 원본 SHA-256
- 원본 시작·종료 초와 클립 길이
- 판정 근거와 신뢰도 등급
- `train_ready`, `rule_validation`, `needs_review` 구분
- 같은 원본이 train/test 양쪽에 섞이지 않도록 하는 source group

## 부족 장면 판정

다음 중 하나라도 만족하면 해당 상태를 부족하다고 보고한다.

- 명확한 클립이 20개 미만
- 명확한 총 영상 시간이 180초 미만
- 서로 다른 원본 세션이 3개 미만
- 위의 어려운 경계 사례를 양쪽 상태에서 각각 확보하지 못함
- 조명, 안경·얼굴 가림, 카메라 위치 등 촬영 조건 다양성이 한 종류에 치우침

`shortage_report.md`에는 상태별 클립 수, 총 길이, 원본 세션 수, 확보된 변형, 누락된 변형과 다음 촬영 권장 장면을 기록한다. 이 기준은 데이터 충분성을 보장하는 통계적 기준이 아니라, 현재 자료의 명백한 공백을 찾기 위한 최소 점검선이다.

## 검증

- 26개 고유 FocusAI 원본이 모두 처리되었거나 실패 사유가 기록되었는지 확인한다.
- 생성된 모든 MP4를 다시 열어 프레임 수, 길이, 해상도가 유효한지 검사한다.
- 모든 클립의 시작·종료가 원본 길이 안에 있는지 확인한다.
- 파일명 라벨, 폴더 라벨, manifest 라벨이 일치하는지 확인한다.
- 클립·시간 범위 중복을 검사한다.
- 각 클립의 대표 프레임 contact sheet를 만들고 장면 설명과 일치하는지 시각 검토한다.
- `needs_review`는 학습 준비 완료 집계에서 제외한다.
- 원본 영상과 기존 프로젝트 파일의 해시·수정 시간을 변경하지 않는다.

## 오류 처리와 안전 경계

- 열리지 않거나 메타데이터가 비정상인 영상은 건너뛰고 원인과 경로를 기록한다.
- 디스크 공간이 부족하면 새 클립 생성을 중단하고 이미 만든 결과를 보존한다.
- 원본 영상이나 기존 학습 산출물은 삭제·덮어쓰기하지 않는다.
- 영상과 프레임은 로컬에서만 처리하고 외부 서비스에 업로드하지 않는다.

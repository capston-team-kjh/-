# FocusAI 블라인드 직접 라벨링 재학습 설계

## 배경

현재 `ai/models/state_classifier.pkl`은 영상 장면을 직접 판정한 라벨이 아니라 FocusAI 분석기의 `rule_state` 의사 라벨로 학습되었다. 이 모델의 보고된 정확도는 사람 또는 독립 시각 판정과의 일치율이 아니라 기존 규칙과의 일치율이다. 이번 작업은 기존 런타임 동작, 특징, 클래스와 판정 기준을 바꾸지 않고 학습 라벨의 출처만 독립적인 직접 시각 판정으로 교체한다.

## 목표

- 기존에 준비된 FocusAI 후보 영상 201개를 독립적으로 다시 판정한다.
- 기존 라벨, 폴더명, 장면 설명과 규칙 판정값이 보이지 않는 블라인드 표본을 사용한다.
- `focus`, `drowsy`, `gaze_down`, `gaze_side`, `unknown` 5개 클래스와 현재 판정 의미를 유지한다.
- 새 직접 라벨로 동일한 16개 특징 기반 분류기를 다시 학습하고, 직접 라벨 홀드아웃 세트로 평가한다.
- 새 모델과 학습·평가 산출물로 초안 PR #8을 갱신한다.
- 영상과 프레임은 로컬에서만 처리하고 유료 OpenAI API를 호출하지 않는다.

## 범위 밖

- 운영 분석 규칙, 상태 우선순위, 점수 계산과 API 계약 변경
- 새 상태 클래스 추가 또는 기존 클래스 의미 변경
- 원본 영상 수정, 이동, 이름 변경 또는 외부 업로드
- 기존 라벨을 새 라벨로 복사하거나 의사 라벨을 정답으로 사용하는 작업
- 영상 증강 도입과 모델 구조 교체

## 입력과 블라인드 표본

입력 후보는 `C:\Projects\focusai_training_scenes_2026-07-18`에 준비된 201개 클립이다. 이 클립들은 26개 고유 FocusAI 원본에서 추출되었고 원본 해시와 시간 범위를 manifest로 추적할 수 있다.

블라인드 준비 단계는 다음 규칙을 따른다.

1. 기존 `label`, `cue`, `notes`, 라벨 폴더명과 제안 상태를 새 라벨 manifest로 가져오지 않는다.
2. 원본 해시와 시작·종료 시각으로 안정적인 무작위 `blind_id`를 만든다.
3. 같은 원본의 겹치는 시간 범위를 병합하고 최대 10초 단위의 비중복 판정 구간으로 나눈다. 5초 미만의 나머지는 앞 구간에 합친다.
4. 각 구간에서 시작·25%·50%·75%·종료 시점의 대표 프레임을 추출해 하나의 contact sheet로 만든다.
5. 파일명과 contact sheet에는 `blind_id` 외의 정답 단서를 표시하지 않는다.
6. 졸음의 지속성이나 상태 전환이 contact sheet만으로 불명확하면 같은 `blind_id`의 추가 프레임 또는 짧은 로컬 영상을 확인한다.

기존 라벨은 새 라벨이 모두 동결되기 전까지 새 manifest와 판정 화면에서 조회하지 않는다. 동결 후 비교 감사에만 사용한다.

## 직접 판정 기준

기존 상태 의미를 그대로 적용한다.

- `focus`: 화면 보기, 타이핑, 독서, 필기 등 학습 행동이 이어진다. 고개를 숙여도 손·교재 활동이 이어지면 포함한다.
- `drowsy`: 눈 감김, 고개 떨굼, 움직임 감소와 학습 행동 중단이 지속된다. 짧은 눈 감김과 단순 고개 숙임은 포함하지 않는다.
- `gaze_down`: 학습 행동과 무관하게 아래, 책상 아래 또는 휴대폰을 지속해서 본다.
- `gaze_side`: 머리나 눈이 좌우의 학습 외 대상을 지속해서 본다.
- `unknown`: 얼굴 가림, 저조도, 역광, 프레임 손상 등으로 상태를 신뢰성 있게 판단할 수 없다.

한 구간에 서로 다른 상태가 섞였거나 경계가 불명확하면 억지로 `unknown`을 부여하지 않고 `ambiguous`로 기록해 학습에서 제외한다. `absent`와 `bad_posture`는 기존과 같이 classifier 학습 대상에서 제외하고 감사용 보조 판정으로만 기록한다.

각 판정 행에는 다음 정보를 저장한다.

- `blind_id`
- `direct_label`
- `confidence`: `high`, `medium`, `low`
- 짧은 시각적 판정 근거
- `review_status`: `accepted` 또는 `ambiguous`
- 판정 시각과 라벨 출처 `codex_visual_direct`

## 데이터 흐름

```text
기존 후보 클립 201개
  -> 기존 라벨을 제거한 비중복 10초 블라인드 구간
  -> 5프레임 contact sheet 및 필요 시 추가 프레임/클립 확인
  -> 독립 직접 라벨 manifest
  -> 원본 source group 기준 train/test 분리
  -> 기존 분석기를 모델 비활성 상태로 실행해 16개 특징 추출
  -> 구간의 직접 라벨을 특징 행에 결합
  -> 기존 SimpleStateClassifier 학습
  -> 직접 라벨 홀드아웃 평가
  -> 모델·CSV·보고서 교체
```

동일 원본에서 파생된 구간은 학습과 테스트 양쪽에 들어가지 않는다. 분할은 라벨링 전에 source group 단위로 고정하고, 증강이나 중복 표본으로 홀드아웃을 오염시키지 않는다.

## 학습과 런타임 호환성

- 특징 이름과 순서는 현재 `FEATURE_NAMES` 16개를 유지한다.
- `SimpleStateClassifier`, 클래스 목록, 모델 파일 경로와 런타임 confidence threshold를 유지한다.
- 특징은 `use_trained_classifier=false`로 추출해 기존 모델 예측이 새 학습 데이터에 되먹임되지 않게 한다.
- 모델 metadata의 `label_source`는 `codex_visual_direct_labels`로 기록한다.
- 학습 및 평가 CSV는 `direct_label`, `source_group`, `blind_id`를 추적할 수 있어야 한다.
- 운영 분석기, worker, API와 프런트 계약은 변경하지 않는다.

## 비교 감사

새 라벨을 동결한 뒤에만 기존 라벨과 비교한다. 비교 결과는 상태별 일치율과 불일치 목록으로 남기되, 기존 라벨로 새 라벨을 자동 덮어쓰지 않는다. 불일치는 contact sheet를 다시 확인하고 명백한 기록 실수만 직접 수정하며 수정 사유를 감사 로그에 남긴다.

## 검증

- 블라인드 manifest에 기존 라벨, cue, notes와 라벨 폴더명이 포함되지 않았는지 검사한다.
- 후보 구간이 모두 `accepted` 또는 `ambiguous`로 종료되었는지 검사한다.
- contact sheet와 직접 라벨의 대응을 표본 감사한다.
- source group이 train/test에 교차하지 않는지 검사한다.
- 모델 metadata와 보고서에 의사 라벨 또는 개인 절대경로가 남지 않았는지 검사한다.
- 직접 라벨 홀드아웃에서 accuracy, macro F1, class별 precision/recall/F1과 confusion matrix를 계산한다.
- 기존 AI 단위 테스트, Python 문법 검사, 모델 로드 스모크 테스트와 프런트 빌드를 다시 실행한다.
- 현재 모델보다 점수가 낮더라도 실제 직접 라벨 결과를 그대로 보고하고 규칙 일치율을 모델 정확도로 표현하지 않는다.

## 오류 처리와 안전 경계

- 열리지 않는 클립은 실패 사유를 기록하고 원본을 수정하지 않는다.
- 한 구간의 상태가 혼합되거나 판단 근거가 부족하면 `ambiguous`로 제외한다.
- contact sheet 생성 실패 시 같은 구간을 다른 디코더 또는 개별 프레임 추출로 한 번 재시도한다.
- 기존 모델과 산출물은 새 모델 검증 전까지 보존한다.
- 로그, 프레임, 영상과 개인 절대경로는 Git에 추가하지 않는다.
- 외부 Vision/API, 네트워크 업로드와 유료 추론 호출을 사용하지 않는다.

## 완료 조건

- 새 라벨 데이터가 기존 라벨과 의사 라벨을 참조하지 않고 독립적으로 작성되었다.
- 모든 블라인드 구간이 판정 또는 제외 사유를 가진다.
- 동일 원본 누수가 없는 직접 라벨 train/test 데이터와 재현 가능한 보고서가 생성된다.
- 동일한 런타임 인터페이스로 새 모델이 로드되고 관련 테스트가 통과한다.
- PR #8에서 의사 라벨 모델·보고서가 직접 라벨 결과로 교체되고 라벨 출처가 정확히 설명된다.
